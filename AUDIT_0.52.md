# Audit Web 0.52

Дата: 2026-09-05

## Что проверено

- Reach-математика: placement → channel → flight → line subtotal → Grand Total.
- Частоты @1+…@6+ и монотонность кривой.
- Universe и коэффициенты пересечения.
- Мультиплановый расчёт и выбор флайтов.
- Синтетические subtotal при отсутствии исходного channel total.
- Сплиты: агрегация plan/fact/delta и финансовая сохранность.
- XLSX/XLSM reader.
- Сборка embedded Python core и GitHub Actions.

## Исправленные слабые места

1. **Объединение Reach.** Арифметическое сложение Reach исключено. Итог строится как ограниченное объединение аудиторий.
2. **Нижняя граница union.** Итоговый Reach не может быть ниже крупнейшего составляющего Reach. Коэффициент 0 означает полное пересечение; 1 — независимое объединение; промежуточное значение регулирует только инкрементальный Reach.
3. **Reach >= 100%.** Невозможный результат больше не обрезается. Core останавливает расчёт с ошибкой.
4. **Синтетические channel subtotal.** Больше не создают Reach через SUM(Reach UU) × коэффициент. Reach собирается из detail-строк через bounded union.
5. **Валидация входов.** Universe, Grand Universe, reachability и коэффициенты проверяются на конечность и допустимый диапазон; некорректные значения не исправляются молча.
6. **Пустой выбор флайтов.** [] теперь действительно означает «ничего не выбрано», а не «выбрать всё».
7. **Grand Reach.** Использует ту же единую функцию объединения Reach, что и остальные уровни.
8. **XLSX 1904 date system.** Добавлена поддержка альтернативной системы дат Excel.
9. **Embedded core.** Сборка проверяет, что embedded engine/web_api/xlsx_reader/splits побайтно совпадают с каноническими исходниками.
10. **CI race.** Rebuild workflow умеет безопасно пережить параллельный UI-коммит и не перезаписывает конфликтующие изменения.

## Автоматические проверки

Regression suite покрывает:
- upper/lower Reach bounds;
- order invariance;
- monotonicity @1+…@6+;
- coefficient 0/1 semantics;
- invalid Universe / coefficients;
- impossible source Reach;
- synthetic subtotal Reach;
- empty flight selection;
- plan/fact availability in Splits;
- Excel 1900/1904 date systems.

## Методологические границы, которые не являются багом кода

1. Без deduplicated user-level данных нельзя получить «истинный» cross-platform Reach. Текущий расчёт — planning model между двумя математически корректными границами: полное пересечение и независимое объединение.
2. Grand Total для разных ЦА методологически зависит от корректного общего Grand Universe. Авто-режим использует продуктово согласованную логику; предупреждение о разных ЦА должно сохраняться.
3. Fallback-коэффициенты площадок и auto intersection — эвристики. Их корректность должна калиброваться на исторических фактических данных, а не усложняться кодом без бенчмарка.
4. Парсер рассчитан на LAB/агентские медиапланы, но произвольный Excel невозможно распознать безошибочно без фиксированной схемы. Поэтому новые/неоднозначные площадки и финансовые реконcиляции остаются явно диагностируемыми.

## Итог

После аудита критических математических нарушений не оставлено. Следующий качественный шаг — не усложнение формул, а эмпирическая калибровка коэффициентов на исторических plan/fact данных.
